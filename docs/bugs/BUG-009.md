# BUG-009: Session token cookie missing HttpOnly flag

| Field | Value |
|---|---|
| Module | Session management |
| Severity | High |
| Priority | P1 |
| Environment | OWASP Juice Shop (localhost:3000), Chromium |
| Status | Open |

## Steps to reproduce
1. Log in as any user
2. Open DevTools Console and run: document.cookie
3. Or: DevTools → Network → any request → Cookies tab → check the "token" row

## Expected
The session token cookie has HttpOnly set, so JavaScript cannot read it.

## Actual
`document.cookie` returns the full JWT (`token=eyJ...`). The HttpOnly column is unchecked for the token cookie.

## Impact
Any XSS (e.g. BUG-002) can steal the session token and take over the account. A missing CSP (BUG-008) makes this easier.

## Root-cause hypothesis
The frontend writes the token to a cookie with JavaScript after login, which can never set HttpOnly. It should be set server-side with `Set-Cookie: token=...; HttpOnly; Secure; SameSite=Strict`.
